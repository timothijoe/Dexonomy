# Shadow 到 Wuji 一代的手型、动作与接触联合迁移

日期：2026-10-13。状态：用户已将下一版优先来源由 Allegro 改为 Shadow。后续已实现 Bench2Dex 相关资产筛选、来源提取及首批三阶段联合静态迁移，详见[实际开发记录](bench2dex-dexonomy-asset-transfer-v1.md)；该路线的 Wuji 一代物理成功样本仍未实现。下文保留路线定义时的输入核查和验收计划。

## 路线选择

采用 Dexonomy 已有的 Shadow 抓取初始化 Bench2Dex 原始 Wuji 一代，再联合优化五指手型、阶段动作、实际接触与物理稳定性。两手均为五指，可建立拇指、食指、中指、无名指、小指的一一语义对应，避免 Allegro 四指来源没有小指动作目标的问题。五指对应并不意味着关节角或几何可以直接复制；当前 Shadow 模型有 22 个手指关节，Wuji 有 20 个，仍需校准掌心、指节、轴向和接触面。

Dexonomy 主抓取数据为 Shadow 的 31 类成功抓取，而本地 Allegro 起始样本只有两种指尖模板。Shadow 更适合覆盖多种来源握法。Allegro 方案保留为后续四指迁移对照，本轮不同时扩展两条主线。

## 已核查来源

- `assets/object/Dexonomy_GRASP_shadow/succ_collect/` 可访问，`11_Power_Sphere` 和 `13_Precision_Sphere` 两个成功类别目录均存在。
- 本次重新加载既有开发样本 `sh_large_obj` 并核对 SHA-256，来源未变。该文件含 17 条抓取，三个阶段各为 `[17,29]`，每条由自由腕 7 维加手指 22 维组成。
- 该文件只有 `scene_path`、`scene_scale`、`pregrasp_qpos`、`grasp_qpos`、`squeeze_qpos`，未含实际接触点/法向字段。接触需要根据可信的原场景重建，原标注可提供类别和必要接触组先验，不能冒充逐条执行接触真值。
- 本次抽样来源的 `scene_scale=2.8821271657943726`，需要与场景对象 `scale` 相乘；不能忽略该倍率或为了匹配手大小任意更改物体尺度。
- 三阶段姿态不是完整连续运动记录。新阶段间轨迹、速度与握力应重新生成并标为合成，不宣称恢复了来源实际执行时序。

现有[Wuji2 开发基准](wuji2-benchmark.md)中的 8 条 Shadow 来源及开发/保留划分可作为基础输入，但旧目标是 Wuji2 Beta2，旧结果也未通过动力学；不能作为本次 Wuji 一代迁移完成证据。

## 实施与验收

先在 Shadow 样本的原物体与原尺度上建立一个可复现闭环：

1. 重建并审查源手三个姿态、接触、穿透与必要手指；保留来源文件、索引、场景、倍率及模型哈希。
2. 显式映射五指，用掌心坐标、指长归一化指节方向、弯曲/张开、拇指对掌和指间关系构造 Wuji 初值。
3. 联合优化 pregrasp / grasp / squeeze，保持来源手型与阶段变化，同时满足实际碰撞面接触、限位、自碰撞和腕部路径约束。必要接触组按来源握法指定，不能要求所有类别一律五指承力。
4. 来源 squeeze 仅提供动作方向先验，重新求解 Wuji 的实际握力，避免继承已知可能穿透的收紧姿态。
5. 复用本地 MuJoCo 实际控制、抬升/保持/六方向扰动与承力审计；对执行后的接触组独立验收，防止名义指尖握法变成指节支撑后仍继承类别标签。

同时交付“Shadow 来源 / Wuji 迁移初值 / Wuji 优化后”的同物体和纯手型三阶段对照，分别报告手型误差、阶段动作误差、实际接触、穿透、限位与稳定性。仅能通过显著改变握法才抓住的样本不能算手型/动作迁移通过；无法兼顾的样本记录拒绝原因，不在优化前保证所有样本都成功。

先完成原物体单样本，再扩展固定的小型开发/保留集合。机制验证后优先适配与任务相关的 `13_Precision_Sphere` / `11_Power_Sphere`，再迁移到 Bench2Dex 四球；跨物体与完整机械臂执行仍需额外验证。本轮继续限定为 MuJoCo，不启动 Isaac 或全量资产遍历。
