# Wuji 一代 MuJoCo 抓取第一版

日期：2026-10-13。状态：已完成四种目标球、左右手的局部生成与物理验证开发覆盖。用户明确本次只做 MuJoCo，Isaac 验收由另一台 RTX 机器承接。

## 已交付的范围

- 26 个正式任务 / 77 个资产目录 / 85 个 USD 模型入口的角色清单。21/27 的角色有明确配置，其余建议保持待检查，不能直接变成生成作业。
- 原始 Wuji 左右手、任务真实 USD 碰撞几何、任务尺度与显式质量的局部场景。场景内模型路径相对，可整体复制到另一台机器。
- 球形指尖 / 球形包握两种请求类别，以实际碰撞面而非 tip site 构造接触目标；所有阶段保存具名 20 维手指姿态和物体相对腕位姿。
- 预抓取开手优化、闭手收紧优化、桌面可行方向与离散直线接近检查。
- 真正的物理步推进：位置执行器控制手指，腕部为有限力/力矩的 Cartesian PD 控制。物体仅在场景重置时设置状态，此后保持自由动态刚体；无固定物体、物体位姿控制或逐帧手部瞬移。
- 限位、手物/自碰撞/桌面穿透、实际手支撑、抬起、保持与六方向扰动的逐物理步检查。失败保存原因、状态和实际指令。
- 单样本、固定种子、仅检查、单 worker 批量、身份/输出校验续跑、真实命令物理重放与 ZIP 导出。

当前生成器只支持任务 27 的四种球。瓶罐资产已恢复，但圆柱握持、箱沿握持、机械臂 IK、双手完整任务、训练和 Isaac 执行没有在本版宣称完成。

## 模型与运行约定

位置为米，角度为弧度，所有新位姿四元数为 wxyz。腕部在这里指原手掌根 `*_palm_link`，机械臂末端与掌心的固定变换仍由原始 URDF 清单提供。

原机器是 A100；Isaac Sim 5.1 官方不支持 A100/H100 的无 RT Cores GPU。本机使用 MuJoCo 3.3.3 / EGL，最终 Bench2Dex 验收留给用户的 RTX 机器。

源碰撞保持 URDF/STL 的凸包表示。原始 USD 中的碰撞网格位于 instance proxies 内，已经修正检查器的遍历。原模型的手掌和指根装配凸包存在固有重叠，明确排除直接父子及手掌—前两级指根装配邻接；其余自碰撞仍检查。该排除清单、依据及质量参数写入每个样本，不等同于已完成跨模拟器几何验收。

## 物理参数和控制器

`configs/bench2dex/mujoco_grasp.yaml` 是完整、可版本追踪的设置。手指默认采用 Bench2Dex 源配置中的 stiffness=400、damping=20、effort=800、armature=5e-6，并显式记录其覆盖 URDF effort 的行为。自由腕 PD 是局部验证工具，不等同于 UR5 驱动或可达性。

手指闭合使用实际接触反馈：初次接触暂缓该指的推进，失去接触后重新尝试；压力建立后保持实际电机目标。接近/闭手阶段可以根据球心调整目标；抬起、保持和扰动阶段冻结对象对齐量。球心反馈不直接写物体状态。这样的局部执行可能包含较大的闭手居中运动，必须在接入机械臂时额外检查工作空间和路径。

物理步长 0.5 ms、控制周期 20 ms。当前局部模型显式设置：

- `solref=[0.002,1]`、`solimp=[0.95,0.99,0.001]`，避免默认软接触需要大量穿透才能形成足够支撑力。
- 手/物摩擦分别为 `[2,0.005,0.0001]` / `[0.5,0.005,0.0001]`，`condim=4`，包含声明的 5 mm 软指腹扭转接触近似。
- 椭圆摩擦锥与 `noslip_iterations=10`，抑制软接触模型的摩擦漂移。该参数的定义见 [MuJoCo 3.3.3 XML 文档](https://mujoco.readthedocs.io/en/3.3.3/XMLreference.html#option-noslip_iterations)。

这些参数是公开记录的 MuJoCo 局部设置，尚未与 PhysX 接触参数等价校准。没有放宽既定验证阈值：穿透 2 mm、限位容差 1e-4 rad、抬起 50 mm、保持至少 1 s、相对位移 10 mm、转动 10 度。扰动为世界六方向各 0.5 倍物体重量，持续 0.2 s，之后恢复 0.2 s。

## 实际结果与覆盖

固定批次 `balls_v2`：四种球×左右手×seed 0，共 8 次，5 次通过局部动力学。对三个缺口使用 seeds 1–3 进行额外尝试，并对右手足球尝试球形包握。四个声明的覆盖批次共 20 次，得到 8 个通过样本，覆盖全部 8 个球/手侧单元。

| 球 | 右手通过样本 | 左手通过样本 |
| --- | --- | --- |
| 迷你足球 | Power Sphere，seed 2 | Precision Sphere，seed 0 |
| 网球 | Precision Sphere，seed 0 | Precision Sphere，seed 2 |
| 高尔夫球 | Precision Sphere，seed 0 | Precision Sphere，seed 2 |
| 乒乓球 | Precision Sphere，seed 0 | Precision Sphere，seed 0 |

表中类别为生成条件，尚未独立人工判定实际握法分类。通过样本的实际姿态与接触可用于审查，不能把请求类别直接当成已确认的语义标签。

代表网球右手 seed 0：全过程质心最高上升约 172 mm，其中闭手阶段上升 102.663 mm、单独 lift 阶段上升 69.311 mm；连续保持 1.2 s 的 60/60 个控制帧全部在每个物理子步由手支撑；保持/扰动区间最大相对位移 0.137 mm、转动 0.098 度。最大手物穿透 0.864 mm、自碰撞 0.500 mm、手桌穿透 0。物理轨迹 16,000 步连续，正常阶段物体外力为零，仅扰动阶段有声明的 ±0.28449 N 载荷。

用户提出图中可能没有握住后，已进行[独立接触力/抬升复核](wuji-mujoco-lift-audit.md)：原图样本在保持阶段仅三根手指承力，向上合力 0.569095 N 与重量 0.568980 N 相符，桌面支撑力为零；实际包含指节接触，不满足“五个指尖”的名义目标。最终默认配置样本也确认真实支撑，但其五指接触中包含指节。动力学通过保留，球形指尖类别适配仍未验收。

候选与控制器在开发过程中调试过，不将这 20 次当作总体成功率或保留集评测。早期调试失败以及 `balls_v1` 的 0/8 结果保留；不能只报告成功条数而隐藏失败和成本。

通过数据源索引为 `output/bench2dex_mujoco/success_manifest.json`，各批次有 `summary.json` / `summary.md`。源码、配置、模型、物体和输出文件身份保存在逐样本 `result.json` 中。

## 数据和可复现证据

- `candidate.json`：规划的 pregrasp / grasp / squeeze 目标、碰撞面接触、几何质量及求解停止原因。数值求解未报告收敛的情况不会被隐瞒，最终仍按明确物理判据判断。
- `execution_trace.npz`：控制周期的步前状态、目标、阶段与质量诊断。
- `physics_trace.npz`：每个物理步的实际手指电机目标、腕部力/力矩、扰动力、执行前后状态和接触峰值。相邻步 before/after 状态连续。
- `execution_report.json`：模型、控制器、接触参数、判据和实际结果，固定 `isaaclab_passed=null`、`full_task_passed=null`。
- `executed_pose_record.json`（导出包）：从执行轨迹提取 approach/close/lift/hold 的真实关节与物体相对腕位姿，明确区别于名义优化姿态，不将 hold 冒充独立 squeeze 阶段。
- `execution.xml` / `geometry.xml` 与 `meshes/`：可整体复制的局部模型。

代表网球样本通过实际命令重放：只设置初始状态，之后按记录的目标和外力逐步执行 `mj_step`，16,000 步与原状态分量误差为 0。该重放是同版本局部物理复现，不是 Isaac 或任务评测。

全部 8 个通过样本均已完成命令物理重放，误差为 0，证据在 `output/bench2dex_mujoco/replay_summary.json`。另用最终源码实际执行完整配置默认的 60 mm 接近偏移，网球右手 seed 0 通过；固定 8 单元覆盖表仍按近距离配置统计，不把两种初始范围混合成成功率。

## 勘误与问题修复

早期几何筛选仅使用 `mj_geomDistance`，某些深度相交的网格返回零，曾漏报穿透。现已取距离查询和 `mj_forward` 接触深度的较小值，并补充“查询返回零但实际穿透 5 mm”回归检查。早期几何通过标记不作为当前数据质量证据；对应动力学失败均保存为 rejected，没有进入成功清单。

控制器修复包括：不用数组编号猜测关节功能；根据碰撞面优化开手与收紧；将机械装配碰撞明确排除；选择桌面可行方向和无碰撞接近通道；读取普通 body frame 速度而非惯性中心速度；补偿整手重力力矩；为运动目标提供速度前馈；记录每个物理步而非仅稀疏端点。低层接口依据 [MuJoCo 3.3.3 源码](https://github.com/google-deepmind/mujoco/blob/3.3.3/src/engine/engine_support.c)。

另用一个独立的两爪夹具测试真实抬起/保持/扰动验证器，确认判据能接受已知可保持的物理轨迹。夹具不是 Wuji 样本，不进入成功清单。
