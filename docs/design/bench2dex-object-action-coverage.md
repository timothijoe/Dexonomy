此统计不是官方宣称的“独立物体总数”，也不代表全部模型已下载或验收。

## 抓取类别与任务动作

连续的腕位姿、关节角和执行轨迹无法逐一穷举。可交付目标应是：枚举任务所需的技能和约束，然后在声明范围内覆盖初始状态、左右手、接近方向与环境变化，并通过保留种子测量缺口。

Dexonomy 的类别引导生成用于抓取姿态与接触关系。以下任务技能还需要路径、物理执行和任务级判据：

| 资产的任务角色 | 所需技能示例 | 需要的生成与验证 |
| --- | --- | --- |
| 球、瓶罐、食物 | 抓起、搬运、释放、直立放置 | 接触优化、稳定抓取、可达路径、放置姿态 |
| 箱子、碗、托盘 | 单手或双手握持、搬移、支撑 | 任务指定握持区域与双手/环境碰撞 |
| 酒瓶、调味瓶 | 握持、倾倒、交接 | 持物后的旋转与物理/任务终止条件 |
| 锤子、勺子等工具 | 功能性握持、敲击、舀取 | 把持部位与工作部位分开，补工具操作轨迹 |
| 冰箱、微波炉、水龙头 | 把手接触、开合、旋转 | 部件与关节约束，设备不能整体当作自由抓取物体 |
| 键盘、鼠标、钢琴 | 触碰、按压、滑动 | 接触动作与行程判定，不能用抬起/保持代替 |
| 拼图部件 | 定向、对齐、放置或装配 | 任务指定几何配合与连续碰撞检查 |

同一资产在不同任务中具有不同角色。例如瓶子装箱与倒液体需要的握法/后续运动可能不同。因此生成索引应至少记录物体/部件、任务角色、抓取类别、手侧、腕/关节/接触以及验证结果。

## 推荐推进顺序（讨论建议）

1. 保持第一版两项 Wuji 任务，先覆盖 8 个相关资产及其实际任务角色，先取得单物体真实抓取证据，再生成完整执行演示。
2. 建立“任务资产/部件 × 技能 × 必要手侧 × 初始状态范围”的覆盖表。对适用的单元生成候选，物理筛选并保留失败；不把全部可能笛卡尔组合都列为必须。
3. 接入原演示阶段，替换握法时重算持物相对变换及腕/臂轨迹，完整执行后用原 evaluator 筛选。按固定尝试预算与相同成功演示数量开展 A/B/C 对照。
4. 首版 ACT 按原任务设置分别训练 RGB/状态→整机动作策略。抓取数据可以后续训练独立观测→抓取候选模型；统一多任务策略需明确任务/目标条件及相同输入的比较设置。
5. 对实测失败密集的技能、状态区域或资产优先补数据，并保持开发/评测种子隔离。只有已验证的生成流程稳定后，才扩大到任务相关的其余抓取资产。
6. 297 个编号资产目录可作为后续扩大几何覆盖的候选库。干扰物主要用于目标辨识与视觉/碰撞鲁棒性，并不都需要作为抓取正例。全部 26 任务改用 Wuji 会改变原任务—机器人配对，应另命名为 Wuji 跨任务扩展实验，并验证可达性与任务可执行性。

本方案不承诺覆盖所有可能动作或成功率；覆盖情况由每个单元的生成尝试、通过数、执行成功与失败原因报告。
