# Shadow / Allegro 与 Wuji2 三阶段可视化对照

## 展示内容

`tools/export_wuji2_comparison.py` 从[固定开发样本](wuji2-benchmark.md)和已运行的基线结果生成独立静态网页。每条样本可选择 `pregrasp`、`grasp`、`squeeze` 和两个离线相机角度；每个状态同时展示四张图：原手与同一物体、Wuji2 与同一物体、去掉物体后的原手、去掉物体后的 Wuji2。蓝色代表源手，绿色代表 Wuji2，灰色代表物体。两张手物图使用相同世界坐标、相机和取景尺度；两张纯手型图使用另一个共同相机和尺度。

纯手型图并非简单地把物体从画面删除。导出器将两手的掌心放在原点，取食指根部到无名指根部为横轴、掌心到中指根部为前向轴，建立同一解剖参考系。该坐标变换取自各手 `grasp` 阶段，应用于其三个阶段，以保留同一手在阶段间的相对动作。页面也记录此参考系下的逐指指尖距离，和同物体世界坐标误差并列，方便区分手型差异与全局腕位姿误差。两手的连杆长度、关节轴与指腹形状仍然不同；对齐不意味着姿态或抓取功能等价。

页面首次显示离线 WebP，不依赖 WebGL。与已有 Shadow 图鉴相同，导出器为每个阶段、每个格子生成 12 个水平角度 × 5 个俯仰角度的图片网格；两张基准角度图片在网格中复用。四格在同一观察角度下切换，手物图共用世界坐标相机和尺度，纯手型图共用对齐坐标相机和尺度。拖动一格会同步四格的水平和俯仰；按钮可逐档调整，画面滚转用 CSS 旋转当前图片。浏览器无法创建 WebGL 时自动进入此离线模式；实时 3D 模型载入或画面检查失败也会回到离线模式。

「实时 3D」按需加载仓库自带的 `model-viewer` 和当前四个 GLB，在格内拖动旋转，滚轮缩放；拖动一格会同步四格的观察方向，各模型仍由 3D 查看器自动取景。每张图提供对应 GLB 下载：手物模型含手与物体两组几何，纯手型 GLB 仅含手。浏览器切换样本、阶段或角度时同时更新四张图和 GLB 链接。逐指误差、手物及自碰撞最大穿透、六方向评估结果随阶段显示。网页读取导出的 JSON/WebP/GLB，不接触原始 NPY。

## 数据流与边界

```text
固定清单 + 基线迁移结果 + 手与物体模型
                   ↓
tools/export_wuji2_comparison.py
    ├─ 世界坐标手物图片、视角网格、GLB
    ├─ 掌心/指根对齐的纯手型图片、视角网格、GLB
    └─ index.json + 静态网页
                   ↓
output/wuji2_comparison/（生成目录，不入 Git）
```

导出时验证源文件 SHA-256、源手型、样本索引以及场景尺度是否与迁移结果一致。完整导出有 48 个阶段、11,520 张 WebP（384 张基准图、11,136 张补充视角）和 192 个 GLB，当前生成目录约 319 MB；初始网页只加载当前四张图片，旋转时按需加载相应角度的四张图片，实时 3D 模式再加载四个 GLB。图片用于观察空间关系；基准中 16 条样本六方向评估均未通过，页面明确标为“运动学原型”。当前 `grasp` 阶段的掌心对齐逐指均距，Shadow 8 例平均约 49.6 mm，Allegro 8 例约 102.8 mm；它包含不同手的尺寸和机构差异，仅是手型诊断指标。它与同物体世界坐标中约 1–2 mm 的指尖误差差别很大，说明当前拟合常靠腕位姿补偿，不能从世界指尖误差推断纯手型相似。图片和纯手型近似不构成稳定抓取证据。

复现与打开命令见[操作教程](../../tutorials/visualize_wuji2_comparison.md)。

禁用 WebGL 的本机 Chrome 已通过实际 `8767` 页面验证：自动进入离线多视角，拖动一格后四格同步到同一水平/俯仰索引，滚转后切换阶段及 Allegro 样本仍可加载四张图片。启用 WebGL 的 Chrome 验证了四个 GLB 能载入，以及切换回离线多视角。导出索引中的 11,520 个视角引用与 192 个 GLB 均能在生成目录找到对应文件。用户浏览器中的显示仍需以用户侧反馈为准。
