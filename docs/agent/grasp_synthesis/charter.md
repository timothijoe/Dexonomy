# 抓取生成长期章程

## 目标

从每种手和抓取类型的一份人工模板出发，为多种物体和场景生成无明显穿透、接触丰富且具有物理可行性的灵巧抓取。

## 职责边界

- 本领域负责模板转换、初始化、抓取姿态优化、评估与模板演化。
- 对象和机器人模型的安装与许可由[数据与资源领域](../data_pipeline/charter.md)负责。
- 仿真环境、物理判定和渲染由[仿真与可视化领域](../simulation_visualization/charter.md)负责。
- 学习模型训练不在当前仓库的核心职责内。

## 稳定原则

- 继续使用 Hydra 配置作为运行参数的权威入口。
- 成功结果必须经过明确过滤和仿真评估，文件存在不等于抓取成功。
- 保持原始算法与 ADMM 算法可分别运行，避免在无验证时统一或替换。
- 保留旧数据兼容入口 `legacy_api`，但新数据使用当前字段和场景路径。
- 大规模运行前先用单模板、少量对象和单 worker 完成 smoke test。

## 完成标准

一次生成能力变更至少应通过：配置解析、目标操作 smoke test、代表性成功与失败样本检查、输出字段检查、无异常错误文件，并记录运行环境和命令。

详细当前事实见[生成流水线](evolution/generation-pipeline.md)与[ADMM 优化](evolution/admm-optimization.md)。
