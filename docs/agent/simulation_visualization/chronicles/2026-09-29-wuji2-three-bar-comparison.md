# 2026-09-29：Wuji2 三阶段四格对照与三滑条视角

## 本版解决的问题

用户需要在代表性 Shadow、Allegro 抓取样本上，对照原手与 Wuji Hand 2 Beta 2 的预抓取、抓取、收紧姿态，并在去掉物体后比较手型。用户浏览器无法创建 WebGL 画面，因此实时 GLB 查看器不能作为唯一的旋转入口。本版沿用 [Shadow 图鉴的离线多视角方案](2026-09-29-three-axis-controls.md)：MuJoCo 预渲染水平和俯仰视角，浏览器用三排滑条控制水平环绕、上下俯仰、画面滚转。

## 数据与画面

- 固定样本来自 [`benchmarks/wuji2_retarget_v1.json`](../../../../benchmarks/wuji2_retarget_v1.json)：Shadow 8 条、Allegro 8 条，覆盖开发集和保留集。每条样本有三个阶段。
- 每个阶段显示四格：原手与物体、Wuji2 与同一物体、移除物体的原手、移除物体的 Wuji2。前两格共用世界坐标相机和尺度；后两格按掌心与指根方向对齐，并共用另一组相机和尺度。
- 每格有 12 个水平角度 × 5 个俯仰角度；两张基准角度图片在网格中复用。滚转是浏览器对当前图片做 30° 一档的平面旋转，不会生成新的遮挡信息。
- 拖动任一格同步改变四格的水平与俯仰。三个滑条及箭头可分别调整水平、俯仰、滚转；切换阶段或样本保留当前离线视角。页面继续显示逐指位置误差、穿透和六方向 MuJoCo 评估结果。

## 浏览器行为

页面默认先显示图片。若浏览器无法创建 WebGL，会自动进入离线多视角，显示三排滑条，并把按钮明确标为「实时 3D 不可用」。支持 WebGL 时仍可按需加载四个 GLB；实时模型载入、画面检查失败或超时后回到离线多视角。直接打开生成的 `index.html` 可查看离线图片；实时 3D 需通过 HTTP 服务访问。

## 导出与复现

在仓库根目录，已有基线迁移结果时运行：

```bash
MUJOCO_GL=egl PYTHONPATH=. .viz-env/bin/python tools/export_wuji2_comparison.py
.viz-env/bin/python -m http.server 8767 --bind 0.0.0.0 --directory output/wuji2_comparison
```

同机打开 `http://127.0.0.1:8767/`；局域网内可用服务器 IP 访问。完整的基线结果生成命令、远程端口转发和操作说明见[教程](../../../../tutorials/visualize_wuji2_comparison.md)。导出器复核源文件 SHA-256、手型、样本索引和场景尺度。生成目录 `output/wuji2_comparison/` 不纳入 Git。

## 验证结果与边界

当前导出目录约 319 MB，包含 384 张基准 WebP、11,136 张补充视角 WebP 和 192 个 GLB。索引中 16 条样本、192 个单格阶段视图、11,520 个视角引用均有对应文件。禁用 WebGL 的 Chrome 从实际 `8767` 页面验证了自动离线模式、三个滑条、画面拖动、四格同步、滚转以及阶段和 Allegro 样本切换；启用 WebGL 的 Chrome 验证了四个 GLB 加载及切回离线多视角。用户对三滑条版本反馈“很好”。

本版只覆盖固定的 16 条样本，是姿态诊断工具。离线视角有固定角度和俯仰范围，滚转只改变画面方向。当前基线的 16 条样本六方向 MuJoCo 评估均未通过；指尖接近或画面相似不能称为稳定抓取。迁移和物理评估的状态见[开发样本文档](../../../design/wuji2-benchmark.md)，坐标对齐与页面数据流见[对照设计](../../../design/wuji2-comparison.md)。
