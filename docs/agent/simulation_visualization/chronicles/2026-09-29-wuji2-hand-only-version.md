# 2026-09-29：Wuji2 独立手部动作对应与纯手型版本

## 需求转折

用户先指出，以物体为基准的握法对齐与忽略物体后的“同一手部动作”是两个问题，要求后者单独开发。随后明确要求两个结果版本：一个只有手的优化，一个与物体交互的优化；纯手型版不能只是从原手物图中删去物体。此前[四格对照](2026-09-29-wuji2-three-bar-comparison.md)下排显示的是原物体拟合姿态经掌心对齐后的样子，并不是独立优化结果。

## 当日实现顺序

1. 建立 `benchmarks/hand_action_correspondence_v1.json`，显式映射 Shadow/Allegro/Wuji2 的掌心、指根和指尖。使用各手解剖坐标、中性手型、逐指中性指长定义无量纲形状、相对中性的动作、收拢和阶段动作误差。
2. 新增 `tools/analyze_wuji2_hand_action.py`，在 16 条固定样本上报告原物体拟合的手部动作误差，并单独拟合 Wuji2 的 20 个手指关节。它保留原腕位，但拟合损失只用手部目标。结果输出到忽略的 `output/wuji2_hand_action_v1/`，代码与设计首先提交为 `3266ecc`。
3. 用户澄清需要单独的**可见版本**后，新增 `tools/export_wuji2_hand_only.py` 与独立两栏静态网页。页面使用第二步的关节姿态，只有源手和 Wuji2；三个阶段均导出离线视角和仅含手部的 GLB。旧手物交互页保留，并加入到新页面的跳转。实现提交为 `a2a8fcf`。
4. 本记录补齐纪传体、编年体、当前总览与操作入口；生成资产不纳入 Git。

## 实际证据

16 条样本包含 Shadow 8 条、Allegro 8 条。手部动作拟合后的平均归一化动作误差从 0.530 降到 0.083，但抓取阶段世界指尖均距从 1.73 mm 升到 55.45 mm。`sh_tripod_obj` 的动作误差从 1.261 降到 0.462，世界指尖均距从 1.97 mm 升到 89.18 mm。48 个阶段中 42 个求解器收敛，6 个达到 160 次函数评估上限；76/960 个关节位置距限位小于 0.001 rad。施加固定世界刚体变换后的描述符最大数值差为 `4.64e-15 m`。

新页面完整导出 5,760 张 WebP 与 96 个 GLB；6,048 个索引文件引用均存在，抽样 GLB 重新载入只有手部几何。禁用 WebGL 的 Chrome 在实际 HTTP 页面确认默认 `14_Tripod` 样本可见、实时 3D 标为不可用。实际点击三个旋转控件后，两张手型图片同步切换到 `p03_y01`，滚转显示 30°。同一 HTTP 服务下两版页面均返回 200；原先的 `8767` 手物页面也验证了跳转到新 `8768` 纯手型页。纯手型实时 WebGL 模式本轮未做渲染验收。

## 留下的问题

纯手型优化没有物体接触、穿透或动力学约束，世界指尖误差显著增大，部分关节贴限位。它是动作形态对照，不是物体抓取候选。旧手物交互基线的六方向评估仍是 0/16 通过。下一步需要在开发集联合手部动作、物体指尖、接触和碰撞目标，并在保留集检查阶段连续性、关节裕量和 MuJoCo 评估；用户侧浏览器的实时 3D 表现也仍应单独确认。

当前能力的完整事实维护在[双版本纪传体](../evolution/wuji2-dual-viewers.md)，操作见[纯手型教程](../../../../tutorials/visualize_wuji2_hand_only.md)。
